# Knowledge Index

The map agents read first. One row per module/package: its single responsibility,
where it lives, and links to any decision or pattern doc. Keep rows terse —
this is a lookup table, not documentation. Retire rows that no longer point
anywhere real.

## Cross-cutting

| Concern | Where it's handled | Notes |
| ------- | ------------------ | ----- |
| Secret redaction | `packages/config` (`IS_SECRET_ENV_KEY`, `toRedactedLog`); `packages/channels/src/telegram/client.ts` (`redact`) | Two mechanisms, because Telegram puts the bot token in the URL *path* — no header-based scheme masks it, so every error string is redacted before leaving the client. `IS_SECRET_ENV_KEY` is exhaustive over `Env`: a new env var fails to compile until its secret-ness is declared. |
| Inbound authorization | `apps/hermes/src/handlers/with-allowlist.ts`, `with-private-chat.ts`, composed once in `boot.ts` | Gates are wrappers around the dispatcher, never per-handler checks — a new handler cannot forget one. Empty `TELEGRAM_ALLOWLIST` rejects everyone (fail closed); rejections log the numeric id at warn, which is the intended bootstrap path for discovering your own id. The callback (button-tap) path is deliberately **not** behind these gates: it answers a prompt this bot itself sent into an already-allowlisted private chat, so there is no unauthenticated inbound surface there — see [approval-gate-design](decisions/approval-gate-design.md). **`/oauth/callback` is a second inbound surface these gates do not cover** — it is an HTTP route on the health server, reached by Google's redirect in a browser, not by a Telegram update, so the allowlist has nothing to check. It is defended instead by the **state nonce + PKCE** pair: an unknown, expired, or already-consumed state is rejected with a `400` and no distinction between the three, so a guessed or replayed callback URL cannot complete someone else's connection — see [google-oauth-flow](decisions/google-oauth-flow.md). |
| Tool approvals | `ApprovalGate` port in `packages/agent/src/approval-gate-port.ts`; Telegram impl in `apps/hermes/src/agent/telegram-approval-gate.ts`; inline keyboards + `editMessage`/`answerCallback` in `packages/channels`; wired in `build-agent.ts` and `boot.ts`'s `subscribeGatedDispatch` | A `requiresApproval: true` tool parks the turn on one combined Approve/Deny prompt per batch; unanswered for 5 minutes = denied; a shutdown abort = denied immediately. `createAgent` throws at construction if a gated tool has no gate. **Two stopgaps, not design:** pending approvals are in-memory only (a restart drops them and the tap gets the "expired" reply), and `threadId → chatId` is an in-memory index in `build-agent.ts` populated as a side effect of `getOrCreateThread`, because `ThreadRepo` has no reverse lookup. This gate is why the poller had to stop awaiting message handlers. [approval-gate-design](decisions/approval-gate-design.md), [poller-concurrent-message-dispatch](decisions/poller-concurrent-message-dispatch.md) |
| Google OAuth + token lifecycle | `packages/google-auth` (`connect-flow.ts`, `token-crypto.ts`, `refresh.ts`, `scopes.ts`); `packages/config` (the `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`TOKEN_ENCRYPTION_KEY` all-or-none group); `google_accounts` in `packages/store`; `apps/hermes/src/google/` (oauth client, callback route, refresh sweep) and `apps/hermes/src/handlers/{connect,status,disconnect}.ts` | One credential's life crosses four packages, so the invariants have to be stated once, here. **`getValidAccessToken` is the single seam** for a live access token — the boot-owned sweep and any future request-path tool both go through it, single-flight per `(channel, channelUserId)`; there is no second refresh path to keep in sync. **Single-flight is only sound because the advisory lock guarantees one instance** (the row above): a second process would refresh the same account concurrently and the in-memory `Map` would not see it. **`TOKEN_ENCRYPTION_KEY` never reaches `packages/store`** — the envelope is opaque `jsonb` there, sealed and opened only in `token-crypto.ts`. **The agent never sees a credential**: `/connect`, `/status`, `/disconnect` are command handlers, not tools, so the model cannot mint a consent URL or escalate its own scopes, and `scopes` records what Google *granted*, not what was requested. **A refresh failure is classified, not blanket-handled**: only an explicit `invalid_grant` disconnects and alerts; anything transient leaves the row for the next tick. Two decided deferrals live in the decision docs — no GCM AAD binding on the envelope, and `/disconnect` does not revoke at Google. [google-oauth-flow](decisions/google-oauth-flow.md), [google-token-encryption](decisions/google-token-encryption.md), [google-token-refresh](decisions/google-token-refresh.md), [google-auth-library-dependency](decisions/google-auth-library-dependency.md) |
| Single-instance enforcement | `INSTANCE_LOCK_KEY` (`837_452_910`) + `acquireInstanceLock` in `packages/store/src/advisory-lock.ts` | Dedicated `pg.Client` outside the pool. See [telegram-long-polling-correctness](decisions/telegram-long-polling-correctness.md). |
| Handler idempotency (invariant #4) | A contract for reply-only handlers; enforced in Postgres for the paid one — `apps/hermes/src/handlers/complete.ts` + `packages/store/src/llm-dedupe-repo.ts` | **A message update is no longer replayed on crash** — its offset advances while the handler runs (see the poller row above), so the dedupe key now defends against duplicate *delivery*, not the crash window; a crashed turn is simply lost, logged and not retried. `callback_query` still persists its offset *after* handling and still replays. Echo, `/ping`, `/start` are safe by inspection. The completion handler is not — it spends money — so it claims `telegram:<updateId>` (from `InboundMessage.updateId`) *before* the provider call and marks it completed *after* the reply lands; `llm_dedupe`'s primary key is what makes exact-duplicate delivery a DB guarantee rather than a check-then-insert race. A crash inside that claim→complete window leaves the row `pending`, which **retries** — a named accepted risk: fail-open (one bounded duplicate charge) beats fail-closed (a permanently wedged message). See [telegram-long-polling-correctness](decisions/telegram-long-polling-correctness.md). |
| LLM cost accounting | `packages/llm/src/pricing.ts` + adapter success path; row written via injected `LlmUsageRepo`, wired in `apps/hermes/src/llm/build-llm-provider.ts` | Provider `total_tokens` is authoritative; `input_tokens` stores the cache-**miss** portion only; an unknown model id **throws** `UnpricedModelError` rather than costing `$0` (reversed by 02-telemetry Phase 4), with boot-time `assertModelsPriced` over primary *and* fallback keeping that throw a backstop rather than a live-call hazard. All of it in [llm-cost-accounting](decisions/llm-cost-accounting.md) — read before touching pricing or the usage row. |
| Cache-stable prompt ordering (invariant #6) | `buildRequestBody` in `packages/llm/src/adapter/openai-compatible.ts` | Every request is ordered `tools` → `system` → `messages`, volatile content (timestamps, ids) last. `JSON.stringify` preserves key insertion order, so that order *is* the wire prefix — one moving byte near the front invalidates the provider's prefix cache. Measured live on DeepSeek across an identical 3190-token prefix: cold `cacheHitTokens 0` at $0.001427, warm `cacheHitTokens 3072` at $0.000144 — ~10x. Proof: `packages/llm/src/__tests__/live/cache-hit-tokens.live.test.ts` (`pnpm test:live`, real money). It seeds its prefix per run on purpose: a constant prefix stays warm in the provider's cache, so the cold→warm transition becomes unobservable and the test passes proving nothing. |
| Spend ceiling | `packages/llm/src/budget/` (`resolveBudgetCapUsd`, `assertBudgetNotExceeded`), called first in the adapter's `complete()`; cap from `LLM_MONTHLY_BUDGET_USD`, wired in `apps/hermes/src/llm/build-llm-provider.ts` | The project's only automated defense against a runaway bill (ROADMAP §7). Checked **before** `fetch`, so a breach costs zero provider calls; `>=` blocks at the exact cap; window is the current UTC calendar month off an injected `Clock`. `usageRepo`/`budget` are required adapter options so it can't be bypassed by omission. Bounds spend to within one call's cost of the cap, not an exact stop — [monthly-budget-ceiling](decisions/monthly-budget-ceiling.md). |
| Provider rate-limit backoff | `packages/llm/src/adapter/openai-compatible.ts` (`parseRetryAfterSeconds`, `parseRetryInfoDelaySeconds`); hint carried on `LlmHttpError.retryAfter` | A provider-supplied 429 hint is authoritative and beats computed backoff. Do not assume it arrives as a `Retry-After` header: Google sends none, putting the delay in the body as a `google.rpc.RetryInfo.retryDelay` duration instead, so a header-only reader silently backs off ~8s against a 27-53s ask and burns every retry inside a window that cannot have cleared — the fallback provider was unrecoverable under rate limiting until the body was read. Mirrors `channels`' `TelegramApiError.retryAfter`. Either source is still capped by `nextDelay`'s `MAX_DELAY_MS` and bounded by `MAX_RATE_LIMIT_RETRIES`, so honoring a hint longer than the cap shortens the wait, not the ask — see [d5-deepseek-primary-gemini-fallback](decisions/d5-deepseek-primary-gemini-fallback.md). |
| DB integration test lane | `pnpm test:db` → `packages/store/src/__tests__/db-env.ts` (URL resolution + guard), reached from `apps/hermes`'s DB suites via the `@hermes/store/testing` subpath export; scratch DB named `*_test` | The suites `DELETE FROM llm_usage`, the table the ceiling spends against, so the guard throws on a `TEST_DATABASE_URL` equal to `DATABASE_URL` or not ending in `_test`. One shared guard, not a copy per suite — a suite that re-resolves the URL privately opts out of both checks. Runs serially (`--no-file-parallelism`) because the two `llm_usage` files race. [test-database-isolation](decisions/test-database-isolation.md) — read before adding a DB suite or changing the scripts. |
| CI lanes | `.github/workflows/ci.yml` — one job: `typecheck` → `lint` → `build` → `test` → `test:db`; guard at `packages/llm/src/__tests__/live-lane-excluded.test.ts` | `test` and `test:db` are separate steps because `test:db` needs `--workspace-concurrency=1` (the DB suites share one database), so `TEST_DATABASE_URL` is set on the `test:db` **step**, never the job — job-level would un-skip the `skipIf` DB suites inside `pnpm test` and race them all against one Postgres. `pnpm test:live` is never invoked: it bills real tokens and has been observed at 7/10 Gemini `429`s. The money defense is that CI sets no `LLM_*` secret at all, so live suites skip regardless; the `--exclude` glob and the guard test (which walks the whole workspace and also covers `test:live`'s `--dir` directory) are defense in depth. [ci-lane-policy](decisions/ci-lane-policy.md) |
| Telemetry | Port + event union in `@hermes/core`; buffered recorder and `/stats` math in `packages/telemetry`; `telemetry_events` table, writes and rollups in `packages/store`; wired in `apps/hermes/src/telemetry/build-{telemetry-recorder,stats-repo}.ts` | Three producers today: `packages/llm`'s adapter emits `llm.call`, `packages/agent`'s `runTurn` emits exactly one `turn` per turn (`outcome` narrowed to the `TurnOutcome` union), and `runTurn`'s `finishToolCall` emits `tool.call` once per tool call — `approved` is `false` only for a gated call the human denied, let time out, or that a shutdown abort swept up mid-wait, and `true` on every other row *including* unknown-tool and invalid-args rows, which never reached a handler either; it rides in the `fields` jsonb bag, so nothing aggregates on it yet. A denied row's `duration_ms` is the approval wait, not handler time — known, accepted, see the decision doc. All three carry the real `threadId`/`turnId`. `record()` is synchronous, never throws, and never blocks the paid path — delivery is at-most-once *by design*, the opposite guarantee from `llm_usage`. `telemetry_events` has **no retention policy** and grows unbounded. [telemetry-event-schema](decisions/telemetry-event-schema.md) |
| `/stats` rollups | `apps/hermes/src/handlers/stats.ts` (thin) → `computeStats`/`formatStatsMessage` in `packages/telemetry/src/stats.ts`; repo bound in `build-stats-repo.ts` | **Cost-source split is an invariant:** spend/cap come from `llm_usage` via the *same* `sumCostSince` the budget ceiling reads, so `/stats` can never disagree with the ceiling it reports against; calls, tokens, cache-hit rate, error rate, top tools come from `telemetry_events`. `LlmCallStats` deliberately has no dollar field, so there is nothing a future edit could mis-wire into the spend line. "Error rate" means the share of `llm.call` rows with `is_error = true` — budget rejections are excluded by construction (they emit no event). [telemetry-event-schema](decisions/telemetry-event-schema.md) |
