| Inbound authorization | `apps/hermes/src/handlers/with-allowlist.ts`, `with-private-chat.ts`, composed once in `boot.ts` | Gates are wrappers around the dispatcher, never per-handler checks — a new handler cannot forget one. The callback (button-tap) path is deliberately **not** behind these gates: it answers a prompt this bot itself sent into an already-allowlisted private chat, so there is no unauthenticated inbound surface there — see [approval-gate-design](decisions/approval-gate-design.md). **`/oauth/callback` is a second inbound surface these gates do not cover** — it is an HTTP route on the health server, reached by Google's redirect in a browser, not by a Telegram update, so the allowlist has nothing to check. It is defended instead by the **state nonce + PKCE** pair: an unknown, expired, or already-consumed state is rejected with a `400` and no distinction between the three, so a guessed or replayed callback URL cannot complete someone else's connection — see [google-oauth-flow](decisions/google-oauth-flow.md). |

This gate is why the poller had to stop awaiting message handlers.
