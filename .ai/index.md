## Cross-cutting

| Concern | Where it's handled | Notes |
| ------- | ------------------ | ----- |
| Secret redaction | `packages/config` (`IS_SECRET_ENV_KEY`, `toRedactedLog`); `packages/channels/src/telegram/client.ts` (`redact`) | Two mechanisms, because Telegram puts the bot token in the URL *path* — no header-based scheme masks it, so every error string is redacted before leaving the client. `IS_SECRET_ENV_KEY` is exhaustive over `Env`: a new env var fails to compile until its secret-ness is declared. |
| Inbound authorization | `apps/hermes/src/handlers/with-allowlist.ts`, `with-private-chat.ts`, composed once in `boot.ts` | Gates are wrappers around the dispatcher, never per-handler checks — a new handler cannot forget one. Empty `TELEGRAM_ALLOWLIST` rejects everyone (fail closed); rejections log the numeric id at warn, which is the intended bootstrap path for discovering your own id. |
| Single-instance enforcement | `INSTANCE_LOCK_KEY` (`837_452_910`) + `acquireInstanceLock` in `packages/store/src/advisory-lock.ts` | Dedicated `pg.Client` outside the pool. See [telegram-long-polling-correctness](decisions/telegram-long-polling-correctness.md). |
| Handler idempotency (invariant #4) | A contract for reply-only handlers; enforced in Postgres for the paid one — `apps/hermes/src/handlers/complete.ts` + `packages/store/src/llm-dedupe-repo.ts` | The offset persists *after* handling, so a crash replays exactly one update. Echo, `/ping`, `/start` are safe by inspection. The completion handler is not — it spends money — so it claims `telegram:<updateId>` (from `InboundMessage.updateId`) *before* the provider call and marks it completed *after* the reply lands; `llm_dedupe`'s primary key is what makes exact-duplicate delivery a DB guarantee rather than a check-then-insert race. A crash inside that claim→complete window leaves the row `pending`, which **retries** — a named accepted risk: fail-open (one bounded duplicate charge) beats fail-closed (a permanently wedged message). See [telegram-long-polling-correctness](decisions/telegram-long-polling-correctness.md). |
| LLM cost accounting | `packages/llm/src/pricing.ts` + adapter success path; row written via injected `LlmUsageRepo`, wired in `apps/hermes/src/llm/build-llm-provider.ts` | Provider `total_tokens` is authoritative; `input_tokens` stores the cache-**miss** portion only; unknown model → `warn` + `$0`, never a throw. All of it in [llm-cost-accounting](decisions/llm-cost-accounting.md) — read before touching pricing or the usage row. |
| Cache-stable prompt ordering (invariant #6) | `buildRequestBody` in `packages/llm/src/adapter/openai-compatible.ts` | Every request is ordered `tools` → `system` → `messages`, volatile content (timestamps, ids) last. `JSON.stringify` preserves key insertion order, so that order *is* the wire prefix — one moving byte near the front invalidates the provider's prefix cache. Measured live on DeepSeek across an identical 3190-token prefix: cold `cacheHitTokens 0` at $0.001427, warm `cacheHitTokens 3072` at $0.000144 — ~10x. Proof: `packages/llm/src/__tests__/live/cache-hit-tokens.live.test.ts` (`pnpm test:live`, real money). It seeds its prefix per run on purpose: a constant prefix stays warm in the provider's cache, so the cold→warm transition becomes unobservable and the test passes proving nothing. |
| Spend ceiling | `packages/llm/src/budget/` (`resolveBudgetCapUsd`, `assertBudgetNotExceeded`), called first in the adapter's `complete()`; cap from `LLM_MONTHLY_BUDGET_USD`, wired in `apps/hermes/src/llm/build-llm-provider.ts` | The project's only automated defense against a runaway bill (ROADMAP §7). Checked **before** `fetch`, so a breach costs zero provider calls; `>=` blocks at the exact cap; window is the current UTC calendar month off an injected `Clock`. `usageRepo`/`budget` are required adapter options so it can't be bypassed by omission. Bounds spend to within one call's cost of the cap, not an exact stop — [monthly-budget-ceiling](decisions/monthly-budget-ceiling.md). |
| Provider rate-limit backoff | `packages/llm/src/adapter/openai-compatible.ts` (`parseRetryAfterSeconds`, `parseRetryInfoDelaySeconds`); hint carried on `LlmHttpError.retryAfter` | A provider-supplied 429 hint is authoritative and beats computed backoff. Do not assume it arrives as a `Retry-After` header: Google sends none, putting the delay in the body as a `google.rpc.RetryInfo.retryDelay` duration instead, so a header-only reader silently backs off ~8s against a 27-53s ask and burns every retry inside a window that cannot have cleared — the fallback provider was unrecoverable under rate limiting until the body was read. Mirrors `channels`' `TelegramApiError.retryAfter`. Either source is still capped by `nextDelay`'s `MAX_DELAY_MS` and bounded by `MAX_RATE_LIMIT_RETRIES`, so honoring a hint longer than the cap shortens the wait, not the ask — see [d5-deepseek-primary-gemini-fallback](decisions/d5-deepseek-primary-gemini-fallback.md). |
| DB integration test lane | `pnpm test:db` → `packages/store/src/__tests__/db-env.ts` (URL resolution + guard), reached from `apps/hermes`'s DB suites via the `@hermes/store/testing` subpath export; scratch DB named `*_test` | The suites `DELETE FROM llm_usage`, the table the ceiling spends against, so the guard throws on a `TEST_DATABASE_URL` equal to `DATABASE_URL` or not ending in `_test`. One shared guard, not a copy per suite — a suite that re-resolves the URL privately opts out of both checks. Runs serially (`--no-file-parallelism`) because the two `llm_usage` files race. [test-database-isolation](decisions/test-database-isolation.md) — read before adding a DB suite or changing the scripts. |
| CI lanes | `.github/workflows/ci.yml` — one job: `typecheck` → `lint` → `build` → `test` → `test:db`; guard at `packages/llm/src/__tests__/live-lane-excluded.test.ts` | `test` and `test:db` are separate steps because `test:db` needs `--workspace-concurrency=1` (the DB suites share one database), so `TEST_DATABASE_URL` is set on the `test:db` **step**, never the job — job-level would un-skip the `skipIf` DB suites inside `pnpm test` and race them all against one Postgres. `pnpm test:live` is never invoked: it bills real tokens and has been observed at 7/10 Gemini `429`s. The money defense is that CI sets no `LLM_*` secret at all, so live suites skip regardless; the `--exclude` glob and the guard test (which walks the whole workspace and also covers `test:live`'s `--dir` directory) are defense in depth. [ci-lane-policy](decisions/ci-lane-policy.md) |
| Telemetry | Port only, in `@hermes/core` | Nothing imports an implementation and nothing calls the port yet. `apps/hermes` injects the impl in Phase 2; importing `telemetry` directly would cycle through half the tree. |
